# KCM Agent Instructions

## Core Operating Principles
- Read and understand KCM-WHITEPAPER.md before making changes.
- Understand the repository context before editing files.
- Work within the relevant bounded subsystem and avoid unrelated changes.
- Respect ownership boundaries and existing contracts between subsystems.
- Do not change other subsystems casually or without clear justification.
- Document meaningful changes and the reasoning behind them.
- Validate the result before declaring work complete.

## Working Rules
- Treat the whitepaper as the highest authority for product intent and architecture.
- Preserve repository safety and avoid destructive or speculative changes.
- Keep changes small, explicit, and reversible where possible.
- Do not modify KCM-WHITEPAPER.md.
- Do not expand scope beyond the current task.
